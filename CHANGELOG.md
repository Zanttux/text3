# Changelog

All notable changes are listed here. Versions follow Semantic Versioning.

## [Unreleased]

### Performance
- Typing in a large file no longer rescans the whole text for its line
  endings on every keystroke: per-keystroke work in a 50 MB file drops
  from about 29 ms to 4 ms (Apple M5), so typing keeps up with a 60 Hz
  display (#206).
- Large-file workloads are measured (#206): `scripts/bench/workloads.py`
  has the app itself open 10–300 MB files, index and filter a 1 GB log,
  count matches in a 100 MB file, type into and scroll a 50 MB file
  through its own UI code (`TEXT3_BENCH`), with peak memory per
  workload. Results in docs/PERFORMANCE.md ("Large files"); CI runs a
  smaller set on Linux, Windows and macOS against `bench/budgets.json`.

### Changed
- README and website screenshots retaken from a Text³ build; they no
  longer show the old name. `scripts/screenshots/shoot.py` retakes them
  with an empty config and sample files (#205).

### Added
- App Store build: files you opened come back after a restart inside the
  sandbox. Open Recent, session restore and hot exit keep access through
  security-scoped bookmarks (`bookmarks` in the config folder). Other
  builds are unchanged (#79).

## [0.2.2] — 2026-11-28

First release under the name Text³ (formerly Sanain).

### Performance
- Speed and lightness are measured against other editors and shown on
  GitHub (#179): `scripts/bench/compare.py` (same method for every app:
  launch through Launch Services until the first window, memory after
  idle, app size), results in `bench/results/`, docs/PERFORMANCE.md and
  its charts generated by `scripts/bench/report.py`. Package builds fail
  when a download outgrows `bench/budgets.json`.
### Security
- macOS builds published from main and tags are signed with a Developer
  ID and notarized by Apple (#174, D28): Text³ opens without the
  Privacy & Security › Open Anyway step. Pull-request builds stay
  unsigned; the signing secrets are reachable only from main and tags.
### Added (in preparation)
- Mac App Store support build (#79, docs/APP_STORE.md): `store` build
  flavour (sandboxed, no update check, no default-app offer), entitlements
  and `scripts/package-mas.sh` for a signed store package. Not in the
  store yet: price and review submission are pending.
### Changed
- macOS: Show in Finder asks Finder directly (NSWorkspace) instead of
  starting `open -R`; it also works in the sandboxed App Store build (#79).

### Added
- Default apps (#164): on first start Text³ offers to become the app
  that opens plain text, Markdown, source code, data and (unticked) web
  files; later from Settings › General › Choose file types…, or
  `text3 --default-apps[=plain,markdown,code,data,web]`. macOS and Linux
  set it directly; on Windows Text³ registers itself and opens Settings ›
  Default apps for you to confirm, and the installer offers the same on
  its last page.
- Six popular coding fonts ship with Text³ (#176): JetBrains Mono, Fira
  Code, Cascadia Code, Source Code Pro, IBM Plex Mono and Inconsolata
  (SIL OFL). Settings › Editor › Font lists the fonts Notepad++ and
  Sublime Text users like most first, including Consolas and Menlo when
  installed. The fonts are separate files, loaded only when chosen.
- The Windows installer speaks all 26 interface languages (#169) and
  picks the Windows display language without asking when it is one of
  them. Its texts are Inno Setup's translations (kept in
  packaging/windows/languages); the task names are machine translations
  awaiting review, like the interface's.

### Changed
- Settings, session and macro files are now written with `text3-` headers
  instead of `sanain-` (#171); files from Sanain are still read. A Sanain
  or Text³ 0.2.1 build started afterwards ignores these files.

### Fixed
- Website: deploys no longer fail now and then with "No artifacts named
  github-pages" (#170).
- macOS: the downloaded Text³.app no longer reports "damaged and can't be
  opened" (#166). The bundle is now sealed with an ad-hoc signature, so
  macOS treats it as an unsigned app that can be allowed once in System
  Settings › Privacy & Security › Open Anyway.
- Windows installer: the wizard artwork is no longer drawn upside down
  (#167); the BMPs are now written bottom-up as Inno Setup expects. The
  Welcome and Finished pages show a full-height panel with the mascot
  above the wordmark, the inner pages the mascot's head, as in the NSIS
  installers of Notepad++.
- macOS disk image: the window now has the same artwork panel on the
  left, and on white the app, an arrow and the Applications folder at a
  size that fits the window. The license, README, changelog and
  third-party notices are inside the app (Contents/Resources) instead of
  scattered below the window.

### Changed
- Sanain is now **Text³** ("Text Cubed"; owner decision D27). The window
  title, About, menus (including the macOS app menu), installer, Linux
  desktop entry, website and all 26 interface languages use the new name
  and the approved lynx artwork; the About window shows the lockup on a
  white plate instead of the old tagline, and the AI disclosure is a plain
  sentence instead of a slogan. The command is `text3`, the crates are
  `text3-*`, release files are named `text3-<version>-…`, the Linux
  desktop id is `io.github.zanttux.text3` and the project lives at
  github.com/Zanttux/text3. Older entries below keep the name Sanain.

### Added
- Goto Anything (Edit › Go to Anything…, Cmd/Ctrl+P in both shortcut
  presets), like Sublime Text's: one popup that fuzzy-finds open tabs,
  recent files and the files of the project folder (the Find in Folder
  folder if one was chosen, otherwise the active file's folder). Enter
  opens the file (an open tab is switched to, not reopened);
  Cmd/Ctrl+Enter opens it in the next pane of a split view; Escape
  closes. `name:12` or `name:12:5` opens the file at that line and
  column. A leading `:` goes to a line of the current file, `@` lists
  its symbols (Markdown headings; functions, classes, types and modules
  in Rust, Python, JavaScript, TypeScript/TSX, Go, C, C++, Java, C#,
  Ruby, PHP, Lua, Bash and PowerShell, from the syntax tree) and `#`
  lists the lines containing the text. The folder is listed in the
  background each time the popup opens, up to 50,000 files, skipping
  hidden files and folders (`.git` too), `node_modules`, `target`,
  `build`, `dist`, `__pycache__` and `venv`, never following symbolic
  links; `.gitignore` is not read. The listing stops when the popup
  closes. Up to 500 matches are shown. Screen readers hear the field's
  name and each option with its folder or line, and which is selected.
- Character and word count in the status bar, like Windows Notepad and
  Notepad++: "Characters: 3,456 · Words: 600" for the document, or
  "Characters: 12 of 3,456 · Words: 3 of 600" for the selection (all
  selections summed with multiple cursors). Click it (or press Enter on
  it) for a summary of characters with and without spaces, words, lines
  and bytes in the file's encoding, for the selection and the document.
  Characters are grapheme clusters, the unit the caret moves by (an
  accented letter or an emoji family is one; line breaks are not counted);
  words follow Unicode word boundaries, with each CJK ideograph and
  hiragana character counted as a word. Counting runs in the background
  and never slows typing; files over 8 MB show "—" until the summary is
  opened. Numbers use the language's digit grouping. Settings › Editor ›
  "Show the character and word count in the status bar" (on by default)
  hides it; the log viewer does not show it. The item is a keyboard stop
  in the status bar with a full spoken label.
- Start-up measurement for developers: with `TEXT3_MEASURE_STARTUP=<file>`
  Text³ appends its start-up timings (window, first frame, first frame
  with the opened file) to the file, and with `TEXT3_MEASURE_EXIT=1`
  exits after that frame. `scripts/measure-startup.py` runs repeated
  cold-ish and warm launches with a scratch profile and reports median,
  p95 and memory; results in docs/BENCHMARKS.md.
- Hot exit: quitting (window close, Cmd+Q / Alt+F4, File › Quit, and
  system logout or shutdown where it reaches the app) no longer asks about
  each unsaved tab. Every unsaved tab's text is written to the recovery
  folder and waited for, the session records untitled tabs too (with
  their selection, pins and split layout), and at the next start
  untitled tabs come back untitled and unsaved, edited files come back
  with the edits on top and marked unsaved. If a file changed on disk in
  the meantime, the tab shows your text and the external-change dialog
  opens; nothing is overwritten without your choice. A file that is gone
  keeps its tab (name struck through, "Not found on disk"); saving
  creates it again. Encoding and line endings are kept. Settings ›
  General › "Remember unsaved changes on exit" (on by default) turns it
  off; closing a single tab still asks. A tab that cannot be kept (over
  the snapshot size limit, read-only or full recovery folder) is asked
  about as before, with the reason in the status bar. Recovery snapshots
  now record the disk state the edits were based on, so crash recovery
  also detects files changed since the crash. Several instances can share
  the recovery folder: a starting instance no longer restores (and later
  overwrites) the unsaved tabs of one that is still running.
- A "+" button right after the last tab opens a new untitled tab, the
  same command as File › New Tab (#151). Its tooltip shows the shortcut
  (for example "New Tab (⌘N)"); when the tabs overflow, it stays at the
  right end of the strip and the new tab scrolls into view. It is a
  named button for screen readers and the last keyboard stop of the tab
  strip, after the last tab's close button. Double-clicking the empty
  part of the strip after the tabs also opens a new tab. The strip now
  scrolls the active tab into view whenever it changes.
- Keyboard focus moves between the parts of the window in a fixed order:
  tab strip, find bar, outline, each pane in turn, folder search, status
  bar, and round again. F6 goes to the next part and Shift+F6 to the
  previous one (View → Focus Next Region / Focus Previous Region; both
  can be changed in Settings → Keyboard shortcuts). Tab and Shift+Tab
  follow the same order past the first or last item of a part instead
  of egui's creation order, which never reached the document from the
  tab strip and looped inside the first tab. In the text editor Tab
  still indents; use F6, Escape or Ctrl+Tab to leave it. Escape from the
  tab strip or the status bar returns to the document (after closing a
  status-bar menu, focus stays on its button).
- The status bar's encoding, line ending and indentation are buttons
  like the language: encoding offers Reopen with Encoding and Save with
  Encoding, line ending converts to LF or CRLF, indentation opens the
  Editor settings. Tab moves through them left to right.
- Mermaid state and class diagrams in the Markdown preview, drawn
  natively with the same layered layout as flowcharts (no JavaScript,
  web view or network). `stateDiagram`/`stateDiagram-v2`: states with
  descriptions and `state "Long name" as id`, labelled transitions,
  start and end (`[*]`, per composite), composite states nested up to
  three deep as titled frames, `<<choice>>` (diamond), `<<fork>>` and
  `<<join>>` (bars), notes `left of`/`right of` (also multi-line
  `end note`; drawn as note boxes joined by a dotted line, one layer
  before or after the state), concurrent regions split by `--` (dashed
  frames inside the composite) and `direction`. `classDiagram`: classes
  with attribute and method compartments (`class A { ... }`,
  `A : +member`, `class A["Label"]`), visibility markers as written,
  `$` static (underlined) and `*` abstract (italic) members, method
  return types, generics `List~T~` shown as `List<T>`, annotations such
  as `<<interface>>`, inheritance, composition, aggregation,
  association, dependency, realization and plain links (solid or
  dashed, ends on either side), cardinalities, labels, `namespace`
  frames, notes and `direction`. Styling lines (`classDef`, `style`,
  `cssClass`, `class`) are ignored and `click`, `link` and `callback`
  never run. Other syntax (lollipop interfaces, history states, ...)
  shows the source with the usual note; the flowchart size limits
  apply. Flowcharts also gain two layout fixes: a node that only feeds
  a later node now sits just before it instead of at the top, and a
  self-link's label is drawn beside its loop instead of over it.

### Changed
- Tabs are a tab list for screen readers ("Open files"): each tab is a
  tab named by its file (", unsaved changes" when dirty) with its
  selected state, followed by its close button, now named "Close tab".
  The tab and its close button are the strip's only Tab stops.
- The Settings sections (General, Editor, Appearance, Keyboard
  shortcuts) are a tab list instead of toggle buttons: the selected
  section is the one Tab stop, Up/Down (Left/Right, Home/End) move
  between sections, Tab goes on into the section, which is a named tab
  panel. Opening Settings puts focus on the selected section.
- A Markdown preview is focusable as a whole ("Markdown Preview"), so a
  pane showing only the preview has a keyboard stop.
- Accessibility of the newer views, for keyboard and screen-reader users.
  The CSV grid is a table for screen readers: every cell has its row,
  column and header name and its value, and the active cell follows the
  selection; the JSON, XML and YAML trees are trees whose items say what
  the row shows, their level and whether they are expanded. In both,
  Shift+F10 or the Menu key opens the selected item's menu next to it
  with the first entry focused, and Escape or a menu action brings focus
  back. Trees also take Right (expand, then first child) and Left
  (collapse, then parent). Split panes are named "Pane 1 of 2: file",
  the active one says so, and each pane's editor carries its pane in its
  name. Mermaid diagrams in the preview are images with a short summary
  ("Flowchart. Nodes: 7, links: 8.") and the diagram source as their
  description. Inline editors, the macro and Go to Line prompts and the
  shortcut search field have names; each Change and Reset button in the
  Keyboard shortcuts settings names its command, and Change says when it
  is waiting for a key. Status-bar messages, the Notepad++ import result
  and field errors are announced when they appear. The keyboard focus
  of the grid and trees is drawn as a ring on the selected cell or row.
  New strings in all 26 languages.

### Fixed
- With an editor font chosen (Settings › Editor › Font), every start read
  all system font files in full to find it (about 600 MB on macOS) and
  memory use rose to about 530 MB for several seconds. Font files are
  now only mapped while their names are read: about 110 MB.
- The first window appears 20–35 ms sooner on macOS: it no longer waits
  for the system font list (the "+" button's tooltip is formatted only
  when it shows), and the menu bar is built right after the first frame.
  Inside Text³.app the Dock keeps the bundle's sharper icon.
- Character-level highlighting in Compare no longer depends on machine load for short lines (a 20 ms time limit sometimes produced no highlight).
- Check for Updates works again: it asked GitHub for the "latest release", which leaves out pre-releases, and every Sanain release is one, so it always said there were no releases. It now reads the release list and takes the newest versioned release (skipping drafts and `nightly`).
- With the in-window menu (Windows, Linux), Shift+F6, Shift+F3
  (Notepad++ preset) and Ctrl+Shift+Tab ran the command of the same key
  without Shift; Tab and function-key shortcuts now match their
  modifiers exactly. On macOS,
  Ctrl+Shift+Tab no longer also moves focus as Shift+Tab would.
- In the CSV grid, Shift+Tab from the last cell moves left instead of
  leaving the grid, and the Tab that moves focus into the grid no longer
  also moves the selection.
- Tab past the last cell of the CSV grid (Shift+Tab before the first)
  leaves the grid instead of staying there, and skips the column resize
  handles. Cells and tree labels are no longer separate Tab stops.
- Keyboard focus returns to the document after a command run from the
  command palette (it was lost, so typing went nowhere until a click).
- Turning on the structured view, or moving to a pane that shows one,
  puts keyboard focus in the grid or tree.

### Security
- Checked against Notepad++'s published security advisories (#157; the
  comparison is in docs/RISKS.md). Two gaps fixed:
  - On Windows, `text3 --register`/`--unregister` (also run by the
    installer) started `reg.exe`, and Show in Explorer started
    `explorer.exe`, by bare name, so a program of that name in the folder
    of `text3.exe` (for example a portable copy in Downloads) ran
    instead. Both now run from the Windows system folder by full path;
    on macOS Show in Finder runs `/usr/bin/open`.
  - A Markdown link or image pointing at a network path (`\\host\share\…`,
    `//host/…`) made Windows connect to that host, sending the user's
    sign-in credentials, as soon as the preview showed the image or the
    link was clicked. Such links and images are now refused like
    `file:` links. A `file://host/…` URL from Finder is no longer read
    as a relative path.

## [0.2.1] — 2026-11-27

Patch release with data-safety fixes found by the disk-full drill and a
fresh review (failed in-place saves of hard-linked files, partial macro
backups, structured-view edits after Revert or Reopen with Encoding),
plus the features merged since 0.2.0. Unsigned pre-release builds.

### Added
- Mermaid flowcharts in the Markdown preview, drawn natively (no
  JavaScript, web view or network): `flowchart`/`graph` in all four
  directions, rectangle, rounded, stadium, diamond and circle nodes,
  solid, dotted, thick and invisible links with labels (`|text|` or
  `-- text -->`), chains, `&` groups, quoted labels, `<br>` line breaks
  and `%%` comments. Layered layout; cycles and self-links are drawn;
  diagrams shrink to fit the preview and use the theme colours.
  `style`, `classDef`, `class`, `linkStyle` and `click` lines are
  ignored, so diagram links never open. Other diagram types and
  unsupported syntax show the source with a short note, as do
  diagrams over the size limits (16 KB of text, 150 nodes, 300 links).
  (#136)
- Mermaid in the Markdown preview, round two (still native, no
  JavaScript, web view or network): flowchart subgraphs
  (`subgraph id [title]` … `end`, nested up to three deep) drawn as
  titled frames that never overlap other nodes or frames, links to and
  from a subgraph (drawn to its frame), `<-->`, `--o`, `--x`, `o--o`
  and `x--x` link ends, and hexagon, cylinder, parallelogram, trapezoid
  and double-circle nodes. `sequenceDiagram`: participants and actors
  with `as` aliases, `->`, `-->`, `->>`, `-->>`, `-x`, `--x`, `-)` and
  `--)` messages, self-messages, notes (left of, right of, over one or
  two participants), `autonumber`, activation bars (`activate`,
  `deactivate`, `+`/`-`) and `loop`, `alt`/`else`, `opt`, `par`/`and`,
  `critical`/`option`, `break` and `rect` frames (rect colours are
  ignored). Limits: 50 participants, 500 messages and notes, blocks
  nested 8 deep. Other sequence syntax (`box`, `create`, `link`, ...)
  shows the source with the usual note. `direction` inside a subgraph
  is accepted and ignored.

- Editing in the CSV/TSV grid: double-click a cell, or select it and
  press Enter or F2, to edit it inline. Enter commits, Escape cancels,
  Tab commits and edits the next cell; arrow keys move the selection and
  Delete clears a cell. Right-click a cell or row number for Insert Row
  Below and Delete Row. Each change is one undoable edit of the text
  that replaces only that field's characters: other fields, their
  quoting, line endings (CRLF, LF, CR) and a missing final newline stay
  byte for byte. A value is quoted only when it holds the delimiter, a
  quote or a line break, or when the field was already quoted; inner
  quotes are doubled. A cell past the end of a short row is added with
  delimiters. Editing is off for read-only files and while a quote is
  unterminated. Inserting or deleting columns is not offered.

- Editing in the JSON tree: double-click a key or a scalar value, or
  select it and press Enter or F2, to edit it inline (Enter commits,
  Escape cancels). Values are typed as JSON (`42`, `true`, `null`,
  `"text"`); in a string, text without quotes is taken as the string and
  escaped. A value that is not JSON, or a key another member of the
  object already has, shows an inline error and changes nothing.
  Right-click a node for Edit Value, Rename Key, Add After, Add Inside
  and Delete; Up and Down move the selection and Delete removes the
  selected node. Each change is one undoable edit that touches only that
  node's characters: deleting removes exactly one adjacent comma and the
  whitespace between, adding copies the siblings' line ending,
  indentation and colon spacing (inline into an empty `{}` or `[]`), and
  numbers, escapes and formatting elsewhere stay byte for byte. New
  members are named `key` (made unique) and the name field opens
  straight away. Editing is off for read-only files; documents the
  validator rejects show the error instead of a tree.

- Editing in the XML tree, with the same interactions as the JSON tree:
  double-click an element or attribute name, an attribute value or an
  element's text (or select it and press Enter or F2) to edit it inline;
  Enter commits, Escape cancels, Up and Down move the selection and
  Delete removes the selected element or attribute. Right-click for
  Edit Value / Edit Text, Rename, Add Attribute, Add Child, Add After
  and Delete. Each change is one undoable edit that touches only that
  node's characters: an attribute keeps its quote style (`&`, `<` and
  the quote are escaped), text is escaped (`&`, `<`, `>`) and stays
  CDATA when it was and can, renaming an element changes its start and
  end tag together, deleting an element on its own line removes that
  line, and new elements (`<element/>`, renamed straight away) copy the
  siblings' line ending and indentation. Entity and character
  references, comments, the declaration, CRLF and indentation elsewhere
  stay byte for byte. Names follow the XML Name rules (at most one
  colon); an invalid name, a duplicate attribute or a change that would
  make the document invalid XML shows an inline error and changes
  nothing. Entities are still never expanded. Editing is off for
  read-only files.

- Editing in the YAML tree, with the same interactions as the JSON and
  XML trees: double-click a key or a scalar value (or press Enter or F2)
  to edit it inline, Up/Down/Delete keys, and Edit Value, Rename Key,
  Add After, Add Inside and Delete on right-click. Each change is one
  undoable edit of only that node's characters: a value keeps its quote
  style; a string stays a string, so typing `no`, `yes`, `null`, `1.0`,
  `:x`, `#x` or text with leading spaces over one writes it
  double-quoted (no Norway problem), while text typed over a number,
  boolean or null is kept as written when it is one plain value.
  Deleting a block mapping entry or sequence item removes its lines
  (nested lines and a comment on its last line included); new entries
  (`key: null`, `- null`) go on a new line at the same indentation with
  the same line ending. Comments, blank lines, indentation and CRLF
  elsewhere stay byte for byte, and every edit is checked by parsing the
  result again: anything but the expected tree is refused. Flow
  collections (`[…]`, `{…}`), scalars with an anchor or tag, aliases,
  block scalars (`|`, `>`), complex keys and documents after the first
  are shown but read-only, with the reason on hover; deleting the only
  entry of a collection is disabled. Aliases are still never expanded.
  Editing is off for read-only files.

### Fixed
- Editing a CSV grid or a JSON, XML or YAML tree right after Revert or Reopen with Encoding no longer applies positions from the previous text (which could merge cells or corrupt the file): every document now has its own revisions, so views built from the old text are rebuilt.
- Saving a hard-linked file (saved in place on Linux and macOS) on a
  full disk no longer leaves the file truncated: the old contents and
  modification time are written back, the temporary backup is removed
  and the error says the disk is full. Only if that also fails does the
  backup stay, and the error then names it.
- Saving macros over a file from a newer version no longer leaves a
  half-written `macros.N.bak` when the disk fills up; the backup is
  written through a temporary file.

### Changed
- Typing in large HTML, Markdown, PHP and JavaScript files no longer
  highlights the whole file again: each embedded language (scripts and
  styles, Markdown's inline text and fenced code, the HTML around PHP)
  is kept as its own syntax tree, parsed again only where an edit
  reaches it, and only the changed lines are highlighted, with the same
  colours as before. One keystroke in 512 KB went from 272 ms to 15 ms
  (Markdown), 66 ms to 3 ms (HTML) and 112 ms to 6 ms (PHP). After a
  typing pause the background check keeps the faster incremental state
  when it finds nothing to correct.
- Fenced code blocks, HTML blocks and inline HTML in Markdown are
  highlighted as a whole; before, their punctuation and brackets were
  left out of the embedded language (`()` and `{}` in a Rust fence were
  uncoloured).
- Automated disk-full drill (`SANAIN_FULL_DIR`) for saves, recovery
  snapshots, settings, session and macros, run in CI on a tiny
  filesystem on Linux, macOS and Windows.

## [0.2.0] — 2026-11-26

Milestone M2 (tabs, sessions, recovery, search): crash and conflict tests
in place and no known silent data loss. Unsigned pre-release builds for
Windows, macOS and Linux (installers and portable archives); machine
translations accepted for now (D24). Changes since 0.1.0:

### Added
- Syntax highlighting for PHP, Lua, PowerShell and Markdown source (22
  languages in total). PHP files highlight the HTML, JavaScript and CSS
  around `<?php … ?>`; Markdown source colours headings, emphasis
  markers, links, inline code, front matter and fenced code blocks in
  their own language. Detected by extension (`.php`, `.phtml`, `.lua`,
  `.ps1`, `.psm1`, `.psd1`, `.md`…), by shebang (`php`, `lua`, `pwsh`)
  or a leading `<?php`; also selectable in the status-bar language menu
  and recognised as code-fence tags in the Markdown preview. Folding
  follows the syntax: Markdown heading sections, lists and code fences,
  Lua blocks (with `end` kept visible), PowerShell and PHP blocks.
- Split panes can be resized: drag the line between two panes (the
  pointer turns into a resize cursor). A pane keeps at least 120 points
  where the window allows it. Double-click a divider to share that row or
  column evenly again. Adding or closing a pane keeps the other panes'
  proportions.
- The split layout is saved with the session: direction, nesting, which
  file each pane shows, the focused pane and the pane sizes come back on
  the next launch. Panes whose file did not reopen (or that showed an
  untitled document) are left out. Session files from earlier versions
  load as before without a split, a damaged layout is ignored, and
  earlier versions read new session files and simply open the files
  unsplit.
- The split editor holds up to four panes. View › Split Right (Ctrl/Cmd+\,
  formerly Split Editor) adds a pane beside the focused one and the new
  Split Down adds one below it; the first split sets the direction and a
  split the other way stacks panes inside that column or row (one level of
  nesting). Close Pane closes the focused pane, and Focus Next Pane / Focus
  Previous Pane move between panes (no default shortcuts; assign them in
  Settings). Panes start out sharing the space evenly. Split Right no
  longer toggles the split off: use Close Pane. Saved shortcuts for Split
  Editor keep working.
- Settings › Keyboard shortcuts › Import from Notepad++… reads a Notepad++
  `shortcuts.xml` (on Windows `%AppData%\Notepad++\shortcuts.xml`) and
  applies its changed shortcuts for the commands Sanain has (file, edit,
  search, case, comment, zoom and fold commands) as your own overrides.
  Removed shortcuts are removed; macros, run and plugin commands, unknown
  commands and keys are skipped and counted. A command that held an
  imported shortcut gives it up, and the summary reports imported,
  skipped and remaining conflicts. Files over 1 MiB or malformed XML are
  rejected without changing anything; entities are never expanded.
- Saved keyboard macros: Tools → Save Macro… stores the last recorded
  macro under a name (a macro with the same name is replaced), and Play
  Saved Macro… / Delete Saved Macro… pick one from a filtered list, also
  from the command palette. Playing is one undo step. Macros are kept in
  `macros` next to the settings, in a small versioned text format; damaged
  or oversized entries are skipped, never crashing the editor.
- Split editor: each pane shows its tab as the single editor would —
  Markdown source, preview or both, and the JSON/XML/YAML tree or CSV
  grid when the structured view is on. Clicking a preview or tree focuses
  its pane; links and image permissions work from either pane.
- Tools → Format XML re-indents element-only content with the tab's
  indentation as one undo step. Text, mixed content, CDATA,
  `xml:space="preserve"`, comments, tags and attributes stay exactly as
  written, and line endings are kept; malformed XML is reported in the
  status bar and nothing changes.

### Changed
- Syntax highlighting is incremental while typing. The background
  worker keeps the syntax tree of recently highlighted documents,
  re-parses only what an edit touched and, for languages without
  embedded languages, highlights again only the changed lines. A
  one-character edit in a 1 MB Rust file now takes about 12 ms instead
  of 174 ms, in a 512 KB JSON file about 3 ms instead of 81 ms (release
  build, Apple M5). HTML, JavaScript, Markdown and PHP (embedded
  languages) still highlight the whole file, but folds reuse the tree.
  In broken or ambiguous code an incremental parse can differ from a
  fresh one, so after a 300 ms pause in typing the document is analysed
  once more from scratch and the colours and folds settle on that
  result.

### Fixed
- Notepad++ shortcut preset: Mod+D was both Duplicate Line and Select
  Next Occurrence; it is Duplicate Line only, as in Notepad++. A test now
  checks that no two commands share a shortcut in any preset (#121).
- Windows release builds show `--help`, `--version`, `--register`,
  `--unregister` and CLI usage errors in the parent console. Output may
  appear after the shell prompt (normal Windows behaviour); GUI launches
  still do not open a console window.
- Right-clicking the right half of the last selected glyph preserves the
  selection. Double-clicking punctuation or whitespace between words
  selects that run instead of a neighbouring word (#113, #114).
- Windows: "Open with Sanain" from Explorer failed for every file
  ("Windows cannot access the specified device, path or file"): the
  registered command used a `\\?\` path. Run the installer again (or
  `sanain --register`) to replace the old entries (#115).
- Clicking × on a tab only activated it instead of closing the document
  (since drag-to-reorder was added) (#110).
- Selecting text with the mouse started one character after the pointer:
  a drag now starts where the button went down (#112).
- Double-click selects the word under the pointer (or the run of spaces
  or punctuation), and triple-click the whole line with its line break
  (#113).
- Right-click in the editor opens a menu with Cut, Copy, Paste and Select
  All. Right-clicking inside the selection keeps it; elsewhere the caret
  moves to the pointer first (#114).

### Added
- Syntax-aware folding: for highlighted languages, fold markers follow
  the Tree-sitter syntax tree (functions, blocks, classes, objects,
  arrays, elements, multi-line comments) instead of indentation, so
  irregularly indented code folds correctly; closing brackets and tags
  stay visible. Plain text, Markdown and very large files still fold by
  indentation.
- Keyboard rectangular selection with Ctrl+Alt+Shift+Arrow (Control+Option+Shift
  on macOS): tab-expanded logical columns, whole graphemes and clamped short
  lines; typing replaces every selected row. Shift+Alt+Arrow keeps line duplication.
- macOS: Sanain appears in Finder's Open With for text, code and data
  files, and files opened from Finder or the Dock open in a tab, at launch
  and while running (#78, ADR 0003).
- Windows: the icon is embedded in sanain.exe, so Explorer, shortcuts and
  pinned taskbar items show it.

### Fixed
- Windows: the window flickered and lagged while being moved; Sanain now
  draws with OpenGL on Windows (`SANAIN_RENDERER=wgpu` restores the
  previous renderer) (#95).
- Windows: starting Sanain no longer opens an extra console window
  (release builds use the GUI subsystem).
- macOS: the menu bar showed "sanain" (the file name) when the program
  was started outside Sanain.app, e.g. with `cargo run`. The executable
  now carries an embedded Info.plist with the name "Sanain".
- Regular-expression find and replace split CRLF line endings: `.` and
  `$` treated the CR as part of the line, so e.g. replacing `.*$` or
  trailing spaces left a bare LF. Line breaks are now `\r\n`-aware.
- Replace in Files used the pattern as edited after the search, not the
  one that produced the shown results; it now uses the search's own.
- Saving a hard-linked file could overwrite an existing
  `.NAME.sanain-backup` (possibly the only good copy after an earlier
  failed save); a free backup name is chosen now.
- Replace in Files reads each file once (history gets exactly the
  replaced version) and leaves non-UTF-8 files alone.
- UTF-16 files without a BOM that contain only ASCII text opened as UTF-8
  with invisible NUL characters, so typed text was saved in the wrong
  encoding. They now open as UTF-16.
- Saving a file with several hard links (macOS, Linux) replaced it with a
  new file, so the other names kept the old contents. Such files are now
  overwritten in place, after a backup copy of the old contents is
  written next to them (removed when the save succeeds).
- Fewer whole-document copies on the UI thread: syntax highlighting got a
  copy on every keystroke (even for files too large to highlight), the
  comparison copied both documents every frame, and Go to Heading parsed
  the document every frame while open.
- Crash-recovery checkpoints copied the whole document on the UI thread;
  the copy now happens on the writer thread (large files no longer pause
  every few seconds while edited).
- Typing in the find field of a large document froze the window while
  the whole text was copied and searched on every keystroke. Documents
  over 1 M characters are now searched in the background; a newer search
  cancels the older one.
- A large file opened from the menu, or dropped onto the window, could get
  a log viewer that did not refresh while reading (it was given a stale
  UI context).
- The status bar copied and scanned the whole document every frame to
  show its line ending; large files used several times more memory and
  CPU than needed (147 MB file: 1.43 GB → 571 MB).
- Opening a file with a very long line (such as a multi-megabyte minified
  JSON file) crashed Sanain when word wrap was off or the file was too
  large to wrap: the GPU vertex buffer exceeded its limit. Long lines are
  now laid out only around the visible columns.
- With the native macOS menu, Cmd+A, Cmd+Z and clipboard shortcuts in
  the find bar or other text fields now act on that field, not on the
  document.
- Esc now closes the find bar after searching with Enter.
